# 双服装图案修整 Patterns1

对照本地 JK 原正面参考与地雷系原立绘，修整三处可直接通过图案改善的差异：

| 区域 | 安装前差异 | 本轮处理 |
| --- | --- | --- |
| JK 蓝色臂章 | 猫脸线条糊成杂线、重复轮廓 | 沿手臂曲面展开重画猫脸、圆眼、小嘴及下方盾形线 |
| JK 领结 | 原斜线不连贯、交叉格纹缺失 | 两组连续细斜线构成菱形格，恢复统一粉色底面 |
| 地雷岁领结 | 装饰字样与黑花边糊成格子 | 从原立绘局部映射两侧布片与尾带，过滤背景串色 |

JK 图集从 4K 提至 8K。未绘制部分以最近邻复制原像素，每个原像素变成相同的 2×2 像素块；提高尺寸只给新绘图案更多采样空间，并不增加原图其他区域的真实细节。地雷图集维持已有 8K。保护检查分别以复制放大的 JK 基线、原地雷图集为对照，核对实际半精度 UV 的归属，未修改区域的源像素不变；重新 DXT1 压缩和 mip 采样仍可能产生细微差异。

其他差异已经记录：地雷岁胸口挂件仍为原模型的梯形结构，与参考的十字不同；心形宝石与部分白衣料共用 UV；袖口、裙边花饰和 JK 的徽记还有形状及原图分辨率限制。宝石直接补色会误染其他表面，本轮保留原样，未将这些问题写成已修复。地雷岁背面没有本次原立绘的直接依据，不凭空新增图案。

## 包与安装

候选 `zzzzz_Sui_OutfitPatterns1_4_P` 只含两个真实 cook 的 VT package：`T_JK_Base`、`T_Jirai_Base`。两者均为 8192²、14 mip、sRGB、DXT1。没有网格、叶子材质、shader、物理或外观表资源，保留 Hairpin1、Face3、R8 和语音四组三件套。

本机流程：

1. `prepare_baseline.py` 冻结十二个已安装文件，核对 JK 既有 native 载荷，复制已独立读回的两套 native 几何；`map_components.py` 关联来源组件。
2. `author_patterns.py` 按实际 UV0 和三维表面绘制，`verify_surface.py` 核对目标岛、保护表面及 padding，检查 JK 未修改像素块精确重复原 4K 图。
3. `run_blender.py render_review.py` 使用冻结的 native 几何与对应源 PNG 作同机位审看。禁用的物理笼按实际材质槽隐藏。Blender 隐藏、2 线程、低优先级运行。
4. `cook_texture.py` 在隔离项目中单线程、隐藏运行 UE；`package_candidate.py` 白名单打包、独立读取纹理尺寸/mip/bulk，再提取实际解析的最终载荷逐字节核验。
5. `verify_mount.py` 检查两种目录顺序、对比全部保留的有效 package 元数据。审看最终近景与整体后，记录当前图集和图像哈希到私人 `visual-review.json`。
6. `install-verified.ps1` 在游戏退出、门禁及所有基线哈希一致时仅添加三件套；`verify_mount.py installed` 从实际安装集合再次读取纹理 metadata 和载荷。`rollback-verified.ps1` 按安装凭据只移出本轮叠加包。
7. `collect_evidence.py` 输出数值和哈希到 `evidence/outfit-patterns-v1/`。本地参考、衍生贴图、容器和预览均在忽略的 `private/outfit-patterns-v1/`。

依赖本机合法取得的游戏模板、前序私人候选、工具与映射，不能仅用公开仓库独立重建。代码许可不覆盖角色、美术或游戏派生资产。

## 验证边界

离线预览采用源 PNG 和 Blender 着色，未独立解码最终 VT 为像素，不能代表实际游戏 shader、压缩采样、灯光或动作。游戏实测待反馈。不会自动启动、停止或操作游戏、截图、录屏、删除缓存或修改存档。
