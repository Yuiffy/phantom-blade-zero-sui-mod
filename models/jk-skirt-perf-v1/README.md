# JK 裙子性能修整

2026-11-18 23:39:33（北京时间）已安装并完成实际容器独立读回。安装前 21 文件全部保留，新增三件套后为 24 文件；最新 JKFacePolish2 和地雷岁 ChinClean1（含颈圈）均保留。游戏内性能与动态仍待用户复试。

2026-11-18，用户报告换装后两套服装来回切换均降至约 9 帧，并要求复查 JK 裙子成本。另一个会话只读核对了原三件套哈希和共享 32/8 参数，没有取得掉帧时的 cloth trace；因此不把裙子写成游戏掉帧的已证实唯一原因。

此前只以稳定性和穿模验收，未实测共享求解开销，是本次回归的缺口。旧 `zzzzzzzzz_Sui_JKSkirt1_9_P` 已在用户退出游戏后按哈希移入原安装凭据目录的 `rollback`，禁止重新安装。只移出本会话三文件，保留另一个会话新增的 JiraiChoker1 和所有原文件。

`benchmark_ue.py` 在同一项目、同一合成跑步动作及五组布料下按 8/2→32/8→8/2 顺序计时，排除前 60 个预热帧。C++ 分开测量骨骼更新、上下文准备、`Simulate()` 和结果读回；三组各匹配 181 帧。高开销版求解中位数 315.47 ms，对比两次 8/2 为 20.60/20.55 ms；骨骼更新均约 .14 ms。测试为单线程 UE editor commandlet，不是实际游戏帧时间或 FPS。

直接把旧物理网格降回 8/2 未通过拉伸门槛，禁止交付。选中 `coarse64-12x3-delivery` 将隐藏裙子 cage 从 288 点/512 三角形简化为 64 点/96 三角形，保留四个高度圈、每圈 16 点；可见裙面仍为原 1,531 顶点，UV、蒙皮和面索引不变，外扩形状沿用上一版。物理参考仍为 pelvis，MaxDistance 40 cm，独立低位大腿碰撞保留；回位驱动从 .9 降到 .65，阻尼 .8，弯曲刚度 .3。五组布料共享 12 次迭代、3 子步，四组其他 cloth 的各自配置与物理资产保留。

新旧完整合成跑步的相同 181 帧里，新版求解中位数 37.10 ms、p95 42.13 ms，相对旧版 315.47/354.26 ms 约减少 88%。仍高于早先 8/2 设置约 20.6 ms 的成本，不能保证游戏一定恢复某个帧率。`performance_gate.py` 要求匹配帧、五组输出完整、12/3 以内的预算，以及求解中位数和 p95 都不超过高开销版 25%；稳定性门槛保持原值。

30/60 Hz 六组、18 轮连续走停、跑停、蹲起共记录五组 cloth、1,521 粒子。成品量化 GPU 映射重建通过边长比 .70–1.25、固定点 ≤.03 cm、MaxDistance 超出 ≤.15 cm、静态误差 ≤.3 cm、第一实际求解帧 ≤.5 cm；停止后 2 秒内恢复，末半秒抬升 p95≤1.5 cm、最大≤3 cm、位置残差 p95≤3 cm、速度 p95≤1 cm/s，步行抬升 p95≤6 cm。合成跑步采样可见大腿交线累计从裙子优化前 153/333、高开销版 44/131，降为新版 24/54；这是交线数量，不是面积或实机改善百分比。内衬交线累计较旧版增加，仍需图像及实机观察，不隐藏该退步。

改变物理顶点数后，需同步重建完整渲染映射、骨权重和 mask，保留 cloth GUID、asset index 和原 gameplay/ragdoll PA。`FPointWeightMap::Initialize` 会重置 target/enabled，不能只保留 values；`USkeletalMesh` 的旧 DDC 也会在重新载入时恢复失效映射。最终重建后主动使 DDC 失效并 PostEditChange，保存后以全新编辑器读回，再冻结输入重跑完整求解。最初失败的映射及缓存候选仅留 private，不进入安装容器。

`compose.py` 把三个裙子/共享导出、裙面位置和两处完整 64 字节 GPU mapping 合并到**最新有效安装的 JK 身体**。继续沿用原生 OptionalProperty 保留、原游戏及自定义材质验证依赖上下文、两 package 白名单和 CUE 独立读回；上下文不进入成品。成品名为 `zzzzzzzzz_Sui_JKSkirtPerf1_10_P`。`finalize.py --install` 在六组表面、性能、独立读回、人工图像审阅和安装快照均通过后安装；失败只回退新增三文件。

源码与数值证据可保留在仓库；游戏资产、作者工程、测试粒子、预览、工具二进制、原三件套与新容器仅留忽略的 `private/`。`prepare.py` 是本机已有资产的初始化工具，需自行准备合法取得的原依赖，拒绝覆盖已有冻结工程。Blender 后台 2 线程、BelowNormal；UE `-onethread`、BelowNormal，原限制不变，不启动、停止、控制、截图或录制游戏。
