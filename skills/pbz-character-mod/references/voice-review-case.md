# 从网页听审选择到可回退的 v4 语音包

2026-11-15，用户完成二审后要求“保存并替换到游戏”，并决定当前候选先用，以后岁己按钮增加再优化。本轮是 `library-natural-voice-v3` 的选音修订，不增加目标事件，也没有扩大音源检索。v4 已安装、离线核验通过；没有新的游戏实测通过反馈。统计见仓库根目录 `evidence/voice-reviewed-v4.json`，代码和输入要求见 `scripts/voice/README.md`。

## 冻结听审结果，不能根据旧编号猜素材

网页按原声、已安装 WEM 解码和新候选进行对照，并按中英文、事件、MediaID 展示真正使用的位置。声音标签只帮助检索；用户选择的文件哈希、采样区间与上下文才是后续构建输入。短、轻或像自言自语的声音应先让用户听审，不因标签写着“攻击”就认定适合。

先复制听审 manifest 与 review 原件，核对 review 中的 `manifest_sha256`，再冻结二者哈希和完整选择。沿旧 candidate 到新 candidate 的映射更新该旧声音占用的全部槽；保持同一 `(language, MediaID)` 在所检查引用中的一致性。网页编号、候选数量和事件数量都不是独立媒体数量。

这次 12 项问题全部直接选定候选，逐媒体覆盖 `media` 为空；代码只支持这组已实现的语义。网页提供“恢复原版”“按事件分选”和逐媒体覆盖，不代表构建器已经支持这些结果。遇到未实现的选择必须停止并先实现，不可悄悄按默认候选安装。

## 复用原 WEM，新增声音保持试听区间

246 个语言/媒体槽按二审更新，228 个保持 v3 WEM 字节不变；合计中文 238、英语 236。重复使用认可的 WEM，不把已解码试听 WAV 再次有损编码。仅 3 个新候选真实编码，再用 vgmstream 独立解码验证来源哈希、采样数、相关性和 SNR。最终使用 21 个独立片段，不能把 246 个修改槽说成 246 段新录音。

新音频仅来自已有按钮。仅去首尾空白，并对照 context 的采样区间验证内部 PCM 不变。无 TTS、CosyVoice、变声、新 ASR、分离、增益调整、时间拉伸或按原媒体时长强裁。

v3 的 `min(原 WEM 时长, event MaximumDuration)` 是当时的保守选音上限，没有独立运行证据证明它就是强制停止窗口。这次 224 个已选槽超过该旧上限，保留用户试听选中的完整片段，不随意改 native 时长或重新选择。记录此事实，尤其 1.29 秒的候选需要用户检查连续出招时的截断、叠音和动作衔接。离线解码完整不等于游戏播放完整。

## 从最终容器读回，再按凭据切换

沿用 [原库替换方法](voice-library-case.md)：精确 8 个资产，原语言库 bulk 前缀不变，原生 IDs、加载策略、名称、imports、Extras 和索引不变；只追加载荷并修正资源偏移/尺寸及 bank 源大小。本轮最终 529 个独立 `(language, kind, id)` 媒体/bank 载荷，27 个目标事件，42 个已检查事件内共享媒体一致。

独立验证器从冻结选择重新计算预期映射，比较最终容器解包出的真实媒体，而不只相信构建 report。旧报告保持原样；后续公开代码的复核另写目录。构建、听审、离线核验、安装和运行结果分开记录。

安装前确认游戏退出，核对旧三件套和 receipt。**以此刻实际存在的其他 MOD 文件为保护基线**，不要沿用旧 voice manifest 的模型名称：本次模型已经从最早版本换成 v8。旧模型 allowlist 若用于恢复，会误报冲突并阻塞旧语音恢复。创建只调整 compatible_files 的本地恢复 manifest，原音频三件套和原 manifest 保持可核对。

旧 receipt 卸载后会标为 `applied=false`；新安装失败时，不能再无条件用该 receipt 卸载一次，否则恢复流程自己就失败。应先看旧 receipt 状态，仅在卸载未完成时继续核对移除，再恢复已验证旧包。公共代码用临时假 Steam 目录演练新安装失败、部分卸载失败和回退；这些不算真实游戏故障发生的证据。

本次只公开原创代码、网页模板、选择映射及脱敏统计；约 1.256 GB 的 v4 容器含大量原版库数据，仍留本地。公共代码已改为配置目录、裁剪未使用的历史入口，缺少本地原始数据不能运行完整流水线；不能把该整理版说成全新环境一键复现已通过。
