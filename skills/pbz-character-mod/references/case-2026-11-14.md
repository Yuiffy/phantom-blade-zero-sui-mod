# 本次排障案例（build 26367565）

## 观察与对照

1. 旧全服装模型在故友服装加载存档崩溃；撤掉后用户确认同存档正常。
2. 改为黑伤（逃亡）专属的 v3，预览隐约可见模型，但换装仍崩溃。
3. 对照 A 仅用未改动的原外观表，用户确认一次换装无崩溃；这不验证自制模型。
4. 对照 B 克隆部件 ID、仍使用原版视觉资源，仅做离线检查，未安装。
5. native-shaders-v1 移除自制 shader、复用原版材质与真实 VT。安装后用户原话：“不错！真的搞定了！很不错哦～”。按模型总体成功记录，未推断完整战斗和过场覆盖。

## 可证明的不兼容

顺序解析 shader 资源名称表、资源边界、内存镜像头、冻结块和类型依赖，发现：

| 数据来源 | 资源数 | FMaterialShaderMapContent 布局签名 |
| --- | ---: | --- |
| 原版 MA_Character、MAI_Skin、MI_ZeroHun_Cloth_02_b | 12 | d108a9ec286f421d651d039e9fd9cc5ad11f06fc |
| 旧 MOD 三个自编译母材质 | 6 | 79494cd8d7dded7100803ce6765e439546bddefa |

两边声明大小均为 676、平台布局均为 (8,5)。大小一致和字节往返一致都不能推出运行兼容。没有改签名冒充兼容。

崩溃文件有保护，未取得可读栈。因此成功结果支持“材料/着色器依赖修复有效”，但 shader resource、参数映射、VT 格式一起改动，不能声称某个哈希字段已经被唯一因果证明。

## 保持不变与局限

7 个网格完整导出载荷和外观表 payload 与 v3 字节相同；原 5 张绘制 PNG 字节不变。只在黑伤（逃亡）启用完整替换。所有部位暂用原版 cloth 着色，脸部光照尚可调整，微弱自发光未恢复。新衣模型未制作。

## 参考作者与适用性

- [ccd775/GameModdingKnowledge](https://github.com/ccd775/GameModdingKnowledge)，`games/phantom-blade-zero/` 下 TECHNICAL_CONTRACTS、TROUBLESHOOTING、BUILD_PIPELINE、MATERIALS_AND_TEXTURES、DEV_TOOLING。原版父材质、layer 0、VT 方法是关键参考；作者记录的 build 26266538 与本次 26367565 不同，实际参数仍由本机资源确认。
- [StarryNightSquad/Phantom-Blade-Zero](https://github.com/StarryNightSquad/Phantom-Blade-Zero)：额外 Armature root 可能导致换装崩溃，配置/Engine 内容可能引发 global shader 缺失。本包检查不符合这两项，不能把参考故障当成自己的根因。作者未完成的模型移植也不能当作实机成功证据。

公开仓库不复制上游 portable kit 代码；独立 CUE4Parse 工具的本地适配仍留在工作区。此记录是原创总结，非上游文档镜像。
